# GPT-proposed terms vs oracle dictionary

Compares GPT-4o-mini's `proper_term` mode (fed the oracle dictionary) against `gpt_proposed_term` mode (GPT extracts and translates its own terminology, with no access to the reference translation or oracle `proper_terms`) on the `dev_v1/original` 500-line eval set, for all three language pairs. Both runs are zero-shot, so the comparison is apples-to-apples. The research question: how much does an oracle term list actually buy over letting the model infer its own terminology from the source sentence?

This is a **thin wrapper**: no shared-tree results, only `data/`, `scripts/`, and `results/`/`report/` below (self-contained, since this pipeline's output isn't a real `dev_v1/original` variant — no oracle `proper_terms` were used to generate it, so it doesn't belong in the shared `shared/results/dev_v1/` tree alongside `original`/`expand`/`cleaned`/`dictionary`).

This experiment reuses already-cached GPT pipeline output (extract → propose → translate) — no new API calls are made by either script here.

## Comparability caveat

The cached `gpt_proposed_term` run has no `use_few_shot` field, i.e. it was run zero-shot. The parent `proper_term` baseline has both a `zero_shot/gpt/` and a `few_shot/gpt/` variant; only the **zero-shot** one (`shared/results/dev_v1/original/zero_shot/gpt/metrics_summary.json`) is a fair comparison partner — the few-shot variant uses a different prompting setup and would not isolate the effect of oracle vs. self-proposed terminology.

## Why the scoring logic isn't shared with `shared/lib/analysis/metrics_loader.py`

`gpt_proposed_term`'s terminology accuracy/consistency is scored against GPT's own `gpt_proposed_terms` per sample, not the standard `proper_terms`/`random_terms` inventory the shared metrics loader expects — a genuinely different denominator (the term list itself is the thing under test here, not fixed ahead of time). `compute_gpt_proposed_metrics.py` therefore reimplements accuracy/consistency scoring locally rather than reusing the shared loader, to avoid silently changing what's being measured.

For the dev_v1-vs-dev_v2 comparability check (a different axis — test set vs. training set, not term-list variant), see [`dataset_comparison/`](../../dataset_comparison/README.md). For the other term-list construction methods (GPT-expanded, GPT-cleaned, external dictionary), see the parent [`term_expansion/`](../README.md) experiment.
